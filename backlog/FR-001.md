# FR-001: Classify free-text return reasons into fit categories

## User Story

**As a** Category Manager,
**I want** free-text return comments to be automatically classified into fit categories ("too small", "too large", "too tight", "too long", "too short", "true to size", "not fit-related"),
**so that** I can see the real fit problems of an article instead of only the generic reason codes.

## Context

Today about 40 % of returns contain a free-text comment, which is currently not analyzed. The classification is the data foundation for fit hints on the product page (FR-002).

## Acceptance Criteria

### AC1 – Classification of new return comments
- **Given** a return with a free-text comment is registered in the returns system
- **When** the nightly classification job runs
- **Then** the comment is assigned exactly one fit category and a confidence score between 0 and 1
- **And** the result is stored together with article ID, size and return date

### AC2 – Low confidence
- **Given** the model's confidence score for a comment is below 0.7
- **When** the comment is classified
- **Then** the category is stored as "unclear" and is not used for fit hints

### AC3 – Quality threshold
- **Given** a manually labeled test set of 1,000 return comments
- **When** the model is evaluated against the test set
- **Then** it reaches an accuracy of at least 85 % for the fit categories

### AC4 – Personal data
- **Given** a comment contains personal data (e.g. name, phone number, address)
- **When** it is processed
- **Then** personal data is removed before the comment is sent to the classification model

## Dependencies
- Access to the returns data in the data warehouse
- Labeled test set (to be created together with Customer Service)
